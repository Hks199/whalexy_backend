Operational flow design

These arrows show processing order, not database constraints.

Access: users / user_roles → vendor_users → select vendors → vendor_settings → authorized business operations.
Messaging: Meta webhook → resolve whatsapp_onboarding_connections → find/create contacts → whatsapp_message_logs or instagram_message_logs → update inbox → bots / away responses / AI → send reply → delivery webhook updates.
Broadcast: whatsapp_templates + campaigns + selected contact_groups → group_contacts → resolve contacts → whatsapp_message_queue → worker → whatsapp_message_logs → delivery status and campaign reporting. campaign_groups is a legacy model table with no confirmed direct links extracted.
Automation: message / comment → bot_flows + bot_replies + user_active_flows OR comment_to_dm_automations + comment_to_dm_executions OR out_of_office_settings + schedules + deliveries → send response. WhatsApp forms persist submissions separately in whatsapp_flow_responses.
Commerce: catalogs + catalog_connections → products → incoming order → whatsapp_orders (JSON item snapshot) + whatsapp_user_states → whatsapp_payments → payment webhook → update order → confirmation.
Store integration: Shopify/WooCommerce webhook → corresponding integration → store order → order notification record → WhatsApp send and status tracking.
Appointment: service + resource → schedules / exceptions / existing claims → hold → appointment + unique slot claims → reminder delivery → WhatsApp notification.
AI: contact messages → conversation_ai_analysis / classification / CX score → optional ai_conversation_handoffs → vendor_ai_usages + ai_operation_traces → aggregate vendor_ai_monthly_invoices.
Advertising: ad_accounts → ad_campaigns → ad_sets + ad_creatives → ads → metrics / conversions / reports. Incoming referral → ad_conversation_attributions → attribution reporting.
Calling: whatsapp_calling_settings → agent authorization + browser signaling → whatsapp_calls → whatsapp_call_events → whatsapp_call_artifacts → retention cleanup.
