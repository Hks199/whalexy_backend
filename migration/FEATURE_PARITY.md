# Whalexy migration status

**Full feature parity has not been achieved. Do not replace the production Laravel backend with this checkout.**

The combined source/SQLite inventory contains 125 table names, 33 modules, 648 route declarations and 592 public controller methods. Route declarations include views, closures, local-only helpers and nested groups. They are not 648 independently verified Node API contracts.

The current audit has **21 grouped remaining work areas**, covering **32 partially implemented source modules and 1 without a dedicated native port**. These areas contain multiple features, so 21 is not an individual-feature count. **0 of 648 legacy route contracts are verified**. Run `npm run migration:audit`, `npm run parity` and `npm run migration:remaining` to regenerate the audit, compatibility gate and [remaining-work report](remaining-work.json); the parity command intentionally fails while compatibility is unverified.

The supplied database/database.sqlite snapshot has been inspected read-only. Its 124 tables and every column are represented in the 138-model Prisma schema, including seven corrected physical column mappings and the native Meta Flow ownership/cache table. All 183 declared SQLite foreign-key links have corresponding Prisma links. The original snapshot's 1,450 rows are preserved and hash-verified in the separate legacy_archive PostgreSQL schema. A separate whalexy_import_validation database now contains 1,400 native rows verified field by field, 50 quarantined rows with verified payload hashes and 15 source owner memberships. Explicit transformations handle names, JSON scalars, UTC dates, missing status/priority and message dates. The quarantine retains 10 messages without contacts, 5 campaigns without templates, 33 records without businesses and 2 messages without campaigns. Import does not fabricate verification or activate provider credentials; campaigns remain paused and flows disabled until their configurations are converted. The active application database has not been replaced. Structural differences and quarantined references still prevent a claim of complete source-data compatibility. See SQLITE_DATABASE_REVIEW.md and native-import-report.json.

## Acceptance gate

`npm run parity` fails until source routes have reviewed Node mappings, current source/implementation hashes, named passing tests and the global acceptance conditions. See CONTRACT_VERIFICATION.md. All source routes are initially pending; the existence of a generic CRUD endpoint must not mark them equivalent. This gate is separate from `npm run check`, which verifies the implemented Node code.

Unknown event/job handlers retain a blocked durable job. They are not silently marked processed. Do not automatically retry an uncertain messaging/email effect after a timeout or worker interruption; reconcile it first.
