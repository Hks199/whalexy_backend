# Quoted replies and original unread counts

Original browser text sends at `POST /vendor-console/whatsapp/contact/chat/send` now accept `reply_to_wamid`. Native `POST /api/v1/vendors/:vendorId/messages/send` text and media bodies accept `replyToWamid`. A quote requires one stored provider message ID for the same business/contact/recipient/sender, excludes reaction messages and failed/cancelled/uncertain targets, and retains the native customer-window, visibility, sender and idempotency requirements. These constraints are stricter than the source Laravel lookup.

The send transaction locks and validates the target, stores `replied_to_whatsapp_message_logs__uid`, builds provider `context.message_id` and reserves a durable queue record atomically. Replays return the stored queue response without another send. Changing the quote with the same idempotency key conflicts. Dispatch revalidates the stored identity and scope; changed, deleted or ambiguous targets cancel the quoted send before the provider call. This guard is a pre-dispatch check, not a guarantee against every change racing the remote call. Existing provider claim/acknowledgement handling applies. Live provider compatibility remains unverified.

`GET /vendor-console/whatsapp/chat/unread-count` now returns source-named `unreadMessagesCount`, `myAssignedUnreadMessagesCount` and `myUnassignedUnreadMessagesCount`, plus `phone_number_id`. Use native bearer/workspace authentication and `vendor.contacts.view`. Select an owned connected sender with `from_phone_number_id` when there is more than one connection. Counts include only incoming `received` messages for WhatsApp/null/empty-platform contacts whose tenant matches the log. Foreign imported links and other sender numbers cannot contribute. Assigned-only actors receive their own total/assigned count and zero unassigned count. Full-visibility actors receive the scoped total and unassigned count. Current membership/API-key permissions are checked in a repeatable-read transaction; no messages are marked read.

Original session-selected sender settings, manage-campaign/messaging authorization aliases, secured/client-model response envelopes, realtime, full billing/demo policy, rich quote previews and original frontend/provider comparison remain pending. The browser media-send/FilePond workflow still needs a separate storage port; native public-URL media quotes do not convert that workflow. Live location remains blocked.
