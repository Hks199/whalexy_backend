# Native bot question answers

Question nodes support `text`, `variable_name`, optional `store_in_field`, `input_type`, `is_required`, `validation_rules` (`min_length`, `max_length`), `error_message`, `conditional_flows` and `default_next_node`. Existing questions without a storage mapping continue to capture a session variable. Stored answers are trimmed.

`store_in_field` names a custom field in the current business. Names must resolve uniquely; foreign, missing or ambiguous fields are rejected. Custom-field nodes continue to use their explicit ID and name. The current field definition determines answer validation, including in side-effect-free previews. Supported types are text, number, email, HTTP/HTTPS URL, calendar date, time and local date/time. Unsupported imported field types block execution. Invalid answers retain the current node and variables, queue a validation prompt and do not write a custom value. Receipt replay cannot create duplicate prompts or values.

Conditions are evaluated in array order. Each has `condition_type`, `condition_value` and `target_node`; the first matching target wins, including explicit `null` to end the flow. Text equality, contains and starts-with comparisons trim and lowercase both operands. Numeric conditions support inclusive positive ranges such as `1-10`, `>=5`, `<=5`, `>5`, `<5`, and numeric equality. Signed/exponent answers are supported with bounded exponent syntax; decimal comparisons preserve large values. No match uses `default_next_node` when present, otherwise the node's normal next connection. All condition and default targets are validated.

Answers, custom-value writes, audit entries, graph progress and queued messages share the inbound transaction. Downstream template/catalog/Meta Flow preparation or rendering failure does not save the answer or advance the session. Field references are revalidated for delayed continuations.

The Laravel reference is `QuestionNodeHandler.php`, particularly `processUserInput`, `evaluateCondition` and `storeUserResponseInCustomField`. This is a native implementation, not a verified legacy route contract. Native calendar/time validation and HTTP/HTTPS-only URLs are stricter than the source's date/time shape checks and general URL validator. Numeric comparisons avoid source float rounding; bounded native numeric syntax and Unicode lowercasing differ from PHP. Questions without mappings preserve existing native session-variable behavior; the source handler requires a mapped field. Mapped text defaults to a 500-character limit; unmapped/native custom-field text retains its existing 4096-character bound unless question rules override it.

Legacy PCRE regex conditions, manual canvas connector precedence, source no-match/standard-flow scenarios, full legacy reply-record/canvas configuration normalization, original error/response/UI contracts and cross-channel processing remain pending. Regex conditions are rejected explicitly; they are not executed as unbounded JavaScript regular expressions or treated as successful conversion.

Verification: `tests/bot-questions.test.ts` covers branch precedence/default/null targets, numeric precision, invalid configuration, typed validation, Unicode lengths, optional answers, previews, field isolation/ambiguity, deleted fields, current field types, receipt deduplication, updates and downstream failure atomicity. `tests/bot-flows.test.ts` retains existing bot workflow coverage. Provider delivery is not exercised live.
