# Contact automation settings

`POST /vendor-console/contacts/:contactIdOrUid/toggle-ai-bot` now adapts the source UUID toggle. Send an empty JSON object, bearer/workspace authentication, `vendor.ai.manage` permission and a valid `Idempotency-Key`. Replays return the same completed toggle result instead of toggling again. A fresh key is a new toggle intent.

Native `POST /api/v1/vendors/:vendorId/contacts/:id/ai` accepts `{ enabled: boolean }` and now shares the guarded service. It retains HTTP 204 on success and requires an idempotency header. The original toggle returns HTTP 200 with `contact_uid`, `isAiChatBotEnabled` and `contact.disable_ai_bot`. Original secured/client-model envelopes are not implemented.

The service rechecks active membership/user/vendor/API-key permissions and assigned visibility. Enabling requires an active native base subscription and paid/admin-override AI addon. Pausing remains available when entitlement expires. The remote endpoint is the configured AI service's vendor-scoped `conversations/automation`; the contact must have a WhatsApp recipient. No credentials are returned.

Enablement remains locally paused until a successful acknowledgement, then AI state, active handoff closure and provider-operation audit commit together. Open/resolved conversation state and CX resolution sequence/history are preserved. Disabling first commits a local pause and audit, then synchronizes the provider. A failed or uncertain pause remains locally paused and retains the existing handoff. A pause failure can therefore change local state while returning an error; this is deliberate protection against further native AI automation.

Durable intent is recorded before effects. Toggles/native settings share the original conversation resolution resource, so an unresolved operation blocks competing automation/resolution sends. Acknowledgements must explicitly indicate success and must not contradict the requested enabled state. Timeout, malformed acknowledgement, authorization/entitlement changes or contact version changes after provider acceptance retain uncertainty for reconciliation; retries do not repeat the effect. Missing configuration or pre-effect validation failures are recorded as rejected. Final commit/audit failures roll back enablement and handoff closure; any earlier local pause persists.

This port does not establish live AI provider compatibility. Original session/messaging authorization, middleware billing/demo rules, secured/client-model responses, translations, realtime refresh and automatic uncertainty recovery remain pending. Other source form updates, local assignments and all background/provider workflows still need a complete audit; sharing a service here does not prove every writer uses these guards.
