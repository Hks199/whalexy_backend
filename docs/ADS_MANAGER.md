# Native AdsManager workflows

These APIs implement part of the original AdsManager domain. They use native JSON contracts and do not establish Laravel frontend or live Meta compatibility.

The prefix is `/api/v1/vendors/:vendorId/ads-manager`. Account/campaign reads require `ads.view`, dashboard reads `ads.analytics`, exports `ads.reports`, and mutations `ads.edit`. Connecting, disconnecting and changing remote campaign status additionally require an owner session; API keys cannot perform those operations.

| Method and path | Input and behavior |
|---|---|
| `GET /accounts` | Credential-free owned account metadata |
| `POST /accounts/connect` | `accountId`, `accessToken`; verifies token, configured app, scopes, expiry and actual active account identity before storing an encrypted credential |
| `POST /accounts/:id/sync` | `from`, `to` as UTC `YYYY-MM-DD`; imports complete campaign metadata and daily campaign insights atomically |
| `POST /accounts/:id/structure/sync` | Empty body; imports verified campaign/ad-set/ad metadata atomically, preserving existing budgets and metric windows |
| `DELETE /accounts/:id` | Disconnects locally, removes the native credential and retains historical data |
| `GET /campaigns` | `page`, `limit`, optional `accountId`, `search`, `status`; scoped campaign metadata |
| `POST /campaigns/:id/status` | `status: active` or `paused`, with `Idempotency-Key`; guarded remote status change |
| `GET /dashboard` | `from`, `to`, optional `accountId`; currency-separated totals and daily trends |
| `GET /reports/export.csv` | Same date/account filters; quoted, formula-protected CSV |
| `POST /conversions` | `externalId`, `type`, `currency`, `occurredAt`, optional `value`; provide `campaignId`, `contactId`, or both; immutable outcome with guarded automatic attribution |
| `GET /contacts/:id/attributions` | `page`, `limit`; owned, visible contact history; requires `ads.analytics` and `vendor.contacts.view` |

Configure `META_APP_ID` and `META_APP_SECRET` privately before connection. Tokens need `ads_read` or `ads_management`; remote status changes specifically need verified `ads_management`. Connection checks the token against the configured app, requires an active account and validates currency/timezone. A native account ownership proof is required; imported legacy tokens alone cannot authorize provider calls. Accounts cannot be claimed by another business. Reconnecting with a changed currency requires reconciliation so historical amounts are never silently relabeled.

Synchronization accepts at most 93 inclusive days ending no later than today. Each provider collection has a bound of 50 pages of 100 rows. Pagination uses validated cursors on a fixed Graph host and ignores remote next URLs. Incomplete pagination, malformed numbers, duplicate records, unknown campaign references or currency mismatches leave existing data unchanged. All reads finish before an atomic transaction replaces daily metrics for the returned campaigns in the requested window. Earlier dates and omitted campaigns remain. Changed credentials, a disconnect or revoked membership during a read prevent its commit. Large accounts need a future asynchronous/resumable adapter.

Amounts retain four decimal places. Impressions, reach, clicks and supported action counts must be nonnegative modeled integers. Dashboard totals stay separated by currency. `summedReach` is the sum of daily/campaign reach, not a deduplicated audience. CTR, CPC, CPM, cost per conversation and ROAS use the imported counters and amounts, with zero denominators returning zero. Reports cap results at 10,000 daily rows and reject larger exports. CSV contains no credentials or contact identities.

Remote status changes first confirm the campaign belongs to the connected account. Durable operation claims prevent duplicate mutations: repeat an identical completed request with the same idempotency key to retrieve its result. Changed input conflicts; an unknown provider effect blocks a new key until reconciliation. A successful response records `effectiveStatus: pending_sync`, because delivery status requires a subsequent provider read. Disconnecting does not pause or delete remote campaigns.

Structure synchronization reads complete campaign, ad-set and ad collections on the fixed Graph host. Every row must identify the connected account and have an unambiguous parent in the snapshot. Duplicate legacy IDs, conflicting ownership, incomplete pagination or changed access prevent the entire import. Local objects omitted by the provider are retained; explicit deleted rows receive tombstones and a later returned active row restores them. No budget, targeting or creative payload is invented. The native ad proof records its verified account/campaign/ad-set identity. This endpoint imports metadata, not ad/ad-set insights or creative assets.

Signed incoming WhatsApp messages capture ad referrals under the message/contact receipt lock. Each click ID, or message ID when no click ID exists, has a private native claim. Retries and repeated callbacks retain the original conversation, outcome status and revenue. Only verified, same-business ad/set/campaign chains can match. Unknown ad IDs remain explicitly unmatched; later mirrored IDs can link when a new outcome is recorded, without rewriting prior outcomes. Unsupported source types, malformed IDs and invalid/far-future timestamps do not block message ingestion. Optional HTTPS source URLs are never fetched; URLs with credentials and unsafe schemes are discarded, and UTM values are bounded. Older referrals do not replace the newest contact summary.

Conversions support `lead`, `appointment`, `demo`, `purchase`, `payment`, `signup`, `refund` and `cancellation`. The external ID is unique within the business's native conversion claims; concurrent identical requests return one record and changed payloads conflict. Visible contact-only outcomes select the latest eligible signed referral at or before the outcome time. An unmatched or unproved latest referral cannot fall back to an older matched click. A supplied campaign must match that referral to receive attribution; otherwise the outcome stays unattributed. Currency must match any selected campaign account. Contacts require contact-read access and current visibility. An existing legacy external ID without a native claim requires review. Replays retain their original association even after new clicks arrive.

Each new outcome creates one immutable conversion event. Purchases/payments add and refunds subtract exact four-place attributed revenue; other types change status without changing revenue. Concurrent outcomes serialize per contact, stale outcomes cannot replace the newest status, and revenue overflow rolls back the conversion, event and claim. These local outcomes remain separate from provider insights, avoiding duplicate revenue in dashboard totals. Contact attribution history excludes click IDs, source URLs, raw referrals and contact identities; generic attribution reads also hide private referral fields, require contact-read access and cannot bypass assigned-conversation restrictions. Historical import rows without native claims require reconciliation.

Contact deletion removes attribution history and clears the contact phone identifier from matching financial conversion records, retaining their accounting events and durable claims. Outcome recording locks the contact so it cannot create an orphan concurrently with deletion. Private webhook receipts and audit records retain the existing application retention behavior.

Full OAuth, original views/contracts, campaign/ad-set/creative creation and publication, targeting and budget rules, remote ad/ad-set metrics, creative asset synchronization, historical attribution reconciliation, scheduled/PDF/XLSX reports, large-account synchronization and complete uncertain-operation reconciliation remain unfinished. Generic provider/account/campaign/metric/conversion/budget tables are read-only so they cannot bypass these workflows. Local audience and label data operations remain available separately. Provider calls in automated tests are mocked; no live ad account or spend was changed.
